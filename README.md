# СервисCRM — веб-система управления сервисным центром

Учебный проект в рамках практики на платформе «Октагон» (направление «Веб-разработка», поднаправление «Frontend», задача «Веб-система управления клиентами, записью и заказами сервисного центра», сложность ⚡⚡).

Приложение для приёмщика автосервиса: расписание записей, база клиентов с автомобилями и историей обращений, заказ-наряды со статусной моделью.

## Возможности

- **Расписание по датам** — навигация по дням («←», «→», «Сегодня», выбор даты), фильтры по статусу записи и сотруднику.
- **Записи на обслуживание** — создание записи (клиент → автомобиль → услуга → сотрудник → дата/время). Конфликт по времени у сотрудника отклоняется на стороне «сервера» с понятным сообщением; после ошибки список перечитывается.
- **Статусная модель записи** — Новая → Подтверждена → Клиент прибыл, отмена из активных статусов; переходы ограничены.
- **Клиенты** — поиск по имени, телефону и email (debounce 300 мс), защита от дубля по телефону.
- **Карточка клиента** — контакты, автомобили (добавление/редактирование/удаление с запретом при активных записях), история обращений (записи + заказ-наряды).
- **Заказ-наряды** — создаются из записи после отметки «Клиент прибыл», сквозная нумерация (ЗН-2026-XXXX), статусы: Ожидает диагностики → В работе → Ожидает запчасти → Готов → Выдан.
- **Состояния интерфейса** — скелетоны загрузки, пустые состояния, ошибки загрузки с кнопкой «Повторить», тосты об успехе/ошибке.
- **Надёжность форм** — валидация обязательных полей, блокировка кнопки сохранения на время запроса (повторная отправка невозможна).
- **Переиспользуемые компоненты** — `DataTable`, `ModalBase`, `ConfirmDialog`, `StatusTag`, `ToastStack`, формы `ClientForm`, `VehicleForm`, `AppointmentForm`.

## Стек

- Vue 3 (`<script setup>`, Composition API) + Vue Router 4
- Vite
- Mock-API (`src/api/*`): асинхронные методы с задержкой 250 мс поверх localStorage — имитация backend, который можно заменить реальным HTTP-клиентом, не трогая UI
- Дизайн-токены на OKLCH, шрифты Golos Text и JetBrains Mono
- Без глобального стор-менеджера: данные приходят через API-слой прямо в представления (по предложенной в задании структуре)

## Запуск

```bash
npm install
npm run dev
```

Сборка для продакшена:

```bash
npm run build
```

## Структура проекта

```
src/
├── api/                  # «Серверный» слой (localStorage + задержка + ApiError)
│   ├── db.js             #   хранилище, сиды, ApiError
│   ├── clients.js        #   клиенты: поиск, сохранение, защита от дублей
│   ├── vehicles.js       #   автомобили: CRUD, запрет удаления при активных записях
│   ├── appointments.js   #   записи: создание с проверкой конфликтов, статусы
│   ├── workOrders.js     #   заказ-наряды: создание из записи, статусы
│   └── meta.js           #   справочники услуг и сотрудников
├── components/           # переиспользуемые компоненты
│   ├── DataTable.vue     #   таблица: колонки, слоты, скелетон, пустое состояние
│   ├── ModalBase.vue     #   модальное окно
│   ├── ConfirmDialog.vue #   подтверждение действия
│   ├── StatusTag.vue     #   тег статуса (единая палитра)
│   ├── ToastStack.vue    #   всплывающие уведомления
│   ├── ClientForm.vue    #   форма клиента
│   ├── VehicleForm.vue   #   форма автомобиля
│   └── AppointmentForm.vue # форма записи
├── views/
│   ├── ScheduleView.vue      # расписание по датам
│   ├── ClientsView.vue       # список клиентов с поиском
│   ├── ClientDetailsView.vue # карточка клиента
│   └── WorkOrdersView.vue    # заказ-наряды
├── router/index.js
├── utils/toast.js
└── style.css             # дизайн-токены и базовые стили
```

## Примечания

- Данные хранятся в localStorage браузера (ключ `servicecrm-db-v1`); при первом запуске поднимаются демо-данные: 5 клиентов, 6 автомобилей, записи на сегодня/завтра, 3 заказ-наряда. Сброс — очисткой localStorage.
- Конфликт записей и смена статусов проверяются только на «серверной» стороне API — UI лишь показывает результат.
- Макет из задания требует авторизации в Figma, поэтому интерфейс выполнен в собственной дизайн-системе с сохранением требуемой функциональности.
